# はじめての動作確認手順（初心者向け）

このドキュメントは、プログラミングやパソコンの専門用語に詳しくない方でも、
このマイソク自動生成システムを実際に一度動かして「ちゃんと動くか」を
確認できるように書いたものです。

エンジニア向けの簡潔な手順は [`verification.md`](verification.md) にもありますが、
このドキュメントではそこに出てくる言葉ひとつひとつを説明しながら、
実際の画面操作・コピペするコマンドまで書いています。

> このシステムの全体像がまだよくわからない場合は、先に
> [`../README.md`](../README.md) の「全体像」を読むと理解しやすくなります。

> **重要な注意**: このシステムは、すでに実際の業務で使っているスプレッドシート
> （新規募集家賃管理などのタブがあるもの）とつながっています。テストのつもりで
> 誤って本物の物件データを操作してしまわないよう、必ずテスト専用の行だと
> 確認してから作業してください。不安な場合は、先に管理者へテスト用の行を
> 用意してもらってください。

---

## この手順で確認できること

- Googleスプレッドシートで部屋を選んで「マイソク作成」ボタンを押すと、
  ちゃんとジョブ（作業予約）が登録されるか
- 社内PCで動かすプログラムが、そのジョブを見つけて実際にマイソク画像を
  作ってくれるか
- できあがった画像が正しいサイズになっているか、賃料などの文字が
  鮮明に読めるか
- わざと失敗するような操作をしたときに、システムが正しくエラーとして
  扱ってくれるか

所要時間の目安: 初回は準備も含めて1〜2時間程度を見込んでください
（Googleサービスの設定、パソコンへのソフトのインストールが必要なためです）。

> **現時点での制限**: このマイソク自動生成システムは、まだ「写真をどこに
> 配置するか」という設定が済んでいません。そのため、今回の手順でできる
> 確認は「文字が入ったマイソクの土台（背景）が正しいサイズで出力されるか」
> までで、実際に部屋の写真が貼り込まれた完成品の確認はまだできません
> （準備が整い次第、別途この手順書を更新します）。

## 事前に知っておくと安心な言葉

| 言葉 | 意味 |
|---|---|
| ターミナル（コマンドプロンプト） | パソコンに文字で命令を打ち込む黒い画面のこと。マウスでクリックする代わりにキーボードで操作します |
| コマンド | ターミナルに打ち込む「命令文」のこと。この手順書に出てくる `cd python` のような行がコマンドです |
| GAS（ジーエーエス） | Google Apps Script の略。Googleスプレッドシートの中で動く小さなプログラムのことです |
| Python（パイソン） | 社内PC側で画像を合成するプログラムを書くのに使っている言語の名前です |
| NAS（ナス） | 社内のネットワーク上にある共有の保存フォルダ（会社のファイルサーバのようなもの）です |
| .env（ドットエンブ） | パスワードなどの秘密の設定を書いておく、自分のパソコンだけに置くファイルです。GitHub（ソースコード置き場）には絶対にアップロードしません |
| リポジトリ | このプログラム一式が入っている保管場所（GitHub上のフォルダ）のことです |
| クローンする | リポジトリの中身を、自分のパソコンにまるごとコピーしてくることです |

## 全体の流れ（今から何をするか）

```
① パソコンに必要なソフトを入れる
        ↓
② このリポジトリを自分のパソコンにコピーする
        ↓
③ プログラムが正しく作られているか、自動チェックを走らせる
        ↓
④ 既存のスプレッドシートに、ジョブ管理用の2タブだけ新しく追加する
        ↓
⑤ スプレッドシートで「マイソク作成」ボタンを押してみる
        ↓
⑥ 社内PC側のプログラムを起動して、実際に画像ができるのを確認する
        ↓
⑦ わざと失敗させて、エラーが正しく出るか確認する
```

## 手順 ①: パソコンに必要なソフトを入れる

以下の3つが必要です。すでに入っている場合はこの手順は飛ばして構いません。

- [ ] **Python 3.11以降** — 画像を合成するプログラムを動かすために必要です。
      [python.org](https://www.python.org/downloads/) からダウンロードしてインストールします。
      インストール時に「Add Python to PATH」というチェックボックスが出たら、
      必ずチェックを入れてください（これを忘れるとターミナルからPythonが使えません）。
- [ ] **Node.js** — GAS（スプレッドシート側のプログラム）を送り込むための
      `clasp` というツールを動かすのに必要です。
      [nodejs.org](https://nodejs.org/) から「LTS」と書かれている版をダウンロードします。
- [ ] **Git** — リポジトリをコピーしてくるためのツールです。
      [git-scm.com](https://git-scm.com/downloads) からダウンロードします。

インストールが終わったら、ターミナルを開いて以下を1行ずつ打ち込み、
それぞれバージョン番号が表示されることを確認してください（エラーが出なければOKです）。

```bash
python --version
node --version
git --version
```

> **うまくいかない時は**: 「python は認識されていません」のようなエラーが出た場合、
> パソコンを再起動すると直ることが多いです（インストール時の設定がまだ反映されていない状態）。

## 手順 ②: リポジトリを自分のパソコンにコピーする

ターミナルで、コピーしたい場所（例: デスクトップ）に移動してから、以下を実行します。
`<リポジトリのURL>` の部分は実際のGitHub URLに置き換えてください。

```bash
git clone <リポジトリのURL>
cd autoHP
```

`cd autoHP` の後、ターミナルの表示が `.../autoHP` のような形になっていれば成功です。

## 手順 ③: 自動チェック（テスト）を走らせてみる

ここでは「プログラム自体に明らかな間違いがないか」を、人手を介さず
自動で何十項目もチェックします。まずはこれが全部OKになることを確認しましょう。

### Python側のチェック

```bash
cd python
pip install -e ".[dev]"
pytest -q
```

- `pip install -e ".[dev]"` は、このプログラムを動かすのに必要な部品
  （ライブラリと呼びます）をまとめてインストールするコマンドです。
  少し時間がかかりますが、正常です。
- `pytest -q` を実行すると、最後に

  ```
  25 passed in 0.6s
  ```

  のように「passed（合格）」の件数が表示されれば成功です。
  もし `failed`（失敗）と出た場合は、何かがおかしい状態なので、
  この手順書の最後にある「うまくいかなかったときは」を確認してください。

続けて、コードの書き方に問題がないかのチェックも行います。

```bash
ruff check .
```

`All checks passed!` と表示されれば問題ありません。

### GAS側のチェック

```bash
cd ../gas
npm install
npx tsc --noEmit
```

- `npm install` は、Node.jsで使う部品をインストールするコマンドです。
- `npx tsc --noEmit` は、GAS側のプログラムの書き間違いをチェックするコマンドです。
  何も表示されずに終われば（エラーが出なければ）成功です。

ここまで全部エラーなく終わっていれば、「プログラム自体は正しく作られている」
ことが確認できたことになります。ここからは「実際に動かして使ってみる」確認に進みます。

## 手順 ④: スプレッドシートにジョブ管理用のタブを追加する

このシステムは、部屋の情報を入力するための新しい表を作りません。すでに
業務で使っている実際のスプレッドシート（「新規募集家賃管理」「ITANDI」
「入退去管理」「駐車場価格設定」というタブがあるもの）を、そのまま使います。
今回追加で必要なのは、システムが「今どの部屋の作業をしているか」を記録する
ための、以下の2つの新しいタブだけです。

1. 対象のスプレッドシートに、新しいタブを2つ追加し、それぞれ以下の名前を付けます
   （コピー＆ペースト推奨）。
   - `ジョブ管理`
   - `レイアウト情報`
2. 「ジョブ管理」タブの1行目に、左から順に以下の列名を入力します。

   ```
   batch_id, row_id, building_name, room_name, template_type, status, created_at, claimed_at, completed_at, error_message, output_a3_ref, output_a4_ref, attempt_count, worker_id, background_ref
   ```

3. 「レイアウト情報」タブの1行目には、以下を左から順に入力します（今回の手順では
   まだ使いませんが、後で写真の配置座標を決める際に使うタブです）。

   ```
   template_type, slide_page_id, element_name, element_type, x_emu, y_emu, width_emu, height_emu, rotation_deg, page_width_emu, page_height_emu, captured_at
   ```

### GASをスプレッドシートに紐付ける

1. このスプレッドシートを開いた状態で、メニューの
   「拡張機能」→「Apps Script」を選びます（新しいタブでエディタが開きます）。
2. 開いたページのURLの中に `scriptId=...` に似た文字列（英数字の長い羅列）があります。
   これがこのプロジェクトの「スクリプトID」です。あとで使うのでメモしておきます
   （URL全体ではなく、`/d/` と `/edit` の間にある部分がスクリプトIDです）。
3. ターミナルに戻り、以下を実行して `clasp` というツールをログインさせます
   （ブラウザが開いてGoogleアカウントでのログインを求められるので、
   スプレッドシートと同じGoogleアカウントでログインしてください）。

   ```bash
   cd gas
   npx clasp login
   ```

4. `gas` フォルダにある `.clasp.json.example` というファイルをコピーして
   `.clasp.json` という名前のファイルを作り、中の `scriptId` の値を、
   手順2でメモしたスクリプトIDに書き換えます。

   ```bash
   cp .clasp.json.example .clasp.json
   ```
   （その後、`.clasp.json` をテキストエディタで開いて `scriptId` の値を書き換えてください）

5. 以下を実行して、プログラムをスプレッドシートへ送り込みます。

   ```bash
   npx clasp push
   ```

   `Pushed X files.` のように表示されれば成功です。

6. スプレッドシートに戻り、一度タブを閉じて開き直してください
   （またはページを再読み込みしてください）。上部メニューに
   「マイソク」という新しいメニューが増えていれば成功です。

7. メニューの「拡張機能」→「Apps Script」→左側の「プロジェクトの設定」→
   「スクリプト プロパティ」から、`BACKGROUND_DRIVE_FOLDER_ID` という名前で、
   マイソクの背景画像を一時的に保存するGoogleドライブのフォルダIDを設定します
   （Googleドライブでフォルダを作り、そのフォルダを開いたときのURLに含まれる
   長い英数字の文字列がフォルダIDです）。

> **うまくいかない時は**: 「マイソク」メニューが出てこない場合は、
> ページの再読み込みを試してください。GASのメニューは、スプレッドシートを
> 開き直したタイミングで反映されます。

## 手順 ⑤: 「マイソク作成」ボタンを押してみる

1. 「新規募集家賃管理」タブを開き、**テスト用として使ってよいと確認済みの行**の
   J列（チェックボックスの列）にチェックを入れます
   （本物の募集中の部屋を誤って選ばないよう、必ず確認してから行ってください）。
2. 上部メニューから「マイソク」→「マイソク作成」を選びます。
3. 初回は「承認が必要です」という画面が出ることがあります。これは、
   このプログラムがあなたのスプレッドシートやドライブを操作してよいかを
   確認するGoogleの安全機能です。「許可」を選んで進めてください。
4. しばらくすると、画面に「マイソク作成ジョブを登録しました」という
   ポップアップが表示されます。バッチIDが表示されていれば成功です。
5. 「ジョブ管理」タブを開き、新しい行が2行（自社マイソク・一般マイソクの
   2種類分）追加され、status列が `WAITING`（＝まだ未着手、という意味）
   になっていることを確認します。`background_ref`列にも何か文字列
   （Googleドライブのファイルの識別子）が入っていることを確認します。
6. 手順④で設定したGoogleドライブのフォルダを開き、文字が書き込まれた
   マイソクの土台となる画像が2枚（自社用・一般用）できていることを確認します。
   **この画像を開いて、賃料や住所などの文字が実際に印刷したときに
   読めそうなくらい鮮明かどうかを目で見て確認してください。**
   これは重要な確認ポイントです（文字が全体的にぼやけて見える場合は、
   Googleの仕組み上の制限に引っかかっている可能性があるため、
   開発担当者に共有してください）。

ここまでできれば、「スプレッドシート側の準備（GAS）」は正しく動いています。
ここから先の「実際に画像を作る」部分には、社内PC側のプログラム（Python）と、
画像を保存するNAS（共有フォルダ）が必要です。もしまだNASの用意ができていない
場合は、ここで一旦区切りとして問題ありません（GAS側の確認は完了しています）。

## 手順 ⑥: 社内PC側のプログラムを動かして、実際に画像を作ってみる

ここから先は、NASにファイルを保存できる環境と、Googleの「サービスアカウント」
という特別なログイン情報が必要です。これらは通常、社内のIT担当者や導入担当者が
事前に準備するものです。もしまだ準備がなければ、この手順⑥・⑦は
準備が整ってから行ってください。

> **現時点での制限（再掲）**: 部屋の写真をどこに貼り付けるかという設定が
> まだ済んでいないため、この手順で確認できるのは「手順⑤でできた文字入りの
> 土台画像が、正しいサイズ（A3・A4）でNASに保存されること」までです。
> 実際に写真が貼り込まれた完成品の確認は、別途この設定が終わってから行います。

### 6-1. 設定ファイルを作る

`autoHP` フォルダの一番上（README.mdがある場所）に `.env.example` という
ファイルがあります。これをコピーして `.env` という名前のファイルを作り、
中身を実際の値に書き換えます。

```bash
cd ..
cp .env.example .env
```

`.env` をテキストエディタで開き、以下のような項目を埋めます
（`REPLACE_ME` と書かれている部分を実際の値に書き換えてください）。

- `GOOGLE_SERVICE_ACCOUNT_JSON_PATH`: IT担当者から渡されるサービスアカウントの
  鍵ファイル（.jsonファイル）を、パソコン内のどこかに保存し、そのファイルへの
  パスを指定します（例: `C:\Users\あなたの名前\keys\service-account.json`）。
- `SPREADSHEET_ID`: `1BPLLSSIM37C7aA-zuQydf_RkyFxA9wEfz_Yix2mixk0`
  （実際に使っているスプレッドシートのIDです。スプレッドシートのURLの中の
  `/d/` と `/edit` の間の部分でもあります）。
- `SMB_HOST` / `SMB_SHARE` / `SMB_USERNAME` / `SMB_PASSWORD`: NAS（共有フォルダ）
  への接続情報です。IT担当者に確認してください。

> **重要**: `.env` ファイルは絶対にGitHub等へアップロードしないでください
> （このリポジトリの設定では自動的に除外されるようになっていますが、
> 念のため他の人に共有しないよう注意してください）。パスワードそのものです。

### 6-2. プログラムを起動する

```bash
cd python
python -m autohp.job_poller
```

- 実行すると、ターミナルに「poller_start」のようなログ（記録）が表示され、
  そのまま動き続けます（プログラムが終わらないのは正常です。
  止めたいときはターミナルで `Ctrl+C` を押します）。
- 30秒ほど待ってから、Googleスプレッドシートの「ジョブ管理」タブを見てください。
  手順⑤で作った2行の status が、`WAITING` → `PROCESSING`（作業中）→
  `COMPLETED`（完了）と変わっていけば成功です。
- `COMPLETED` になった行の `output_a3_ref` / `output_a4_ref` 列に、
  ファイルの保存場所が記録されます。NAS側の `自社マイソク/{建物名}/{部屋番号}/`
  （自社マイソクの場合）や `マイソク/{建物名}/{部屋番号}/`（一般マイソクの場合）
  フォルダを確認し、実際にJPEG画像ができていることを確認してください。
- できあがった画像を開いて、手順⑤でGoogleドライブに保存されていたものと
  同じ内容（文字）が、A3サイズの画像として保存されていることを確認します。

## 手順 ⑦: わざと失敗させてみる（エラー確認）

システムが「ちゃんとエラーを検知できる」ことも大事な確認です。

1. 「新規募集家賃管理」タブの**テスト専用の行**で、建物名の欄を一時的に
   `../../etc` のような、明らかにおかしい文字列に書き換えます
   （※これは実データを壊す操作なので、必ずテスト専用の行で、かつ
   元の値を控えてから行ってください。確認が終わったら必ず元に戻します）。
2. J列にチェックを入れて「マイソク作成」を実行する。
3. 「ジョブ管理」タブで、対応する行の status が `ERROR` になり、
   `error_message` 列に「許可されていないパスへのアクセスが要求されました。」
   のような、わかりやすい日本語メッセージが表示されることを確認する
   （パソコン内部のファイルの場所などの専門的な情報が表示されていないことも
   合わせて確認してください。これはセキュリティ上、意図的にそうしています）。
4. 確認が終わったら、建物名を必ず元の値に戻しておきます。

## うまくいかなかったときは

| 症状 | 考えられる原因と対処 |
|---|---|
| `pytest -q` で `failed` が出る | プログラムに問題がある可能性があります。エラーメッセージの内容をそのままコピーして、開発担当者に共有してください |
| 「マイソク」メニューが出てこない | `npx clasp push` が成功しているか確認し、スプレッドシートを再読み込みしてください |
| 「マイソク作成」を押しても何も起きない | Apps Scriptの実行ログ（拡張機能→Apps Script→左側の「実行数」）にエラーが出ていないか確認してください |
| ジョブが `WAITING` のまま進まない | `python -m autohp.job_poller` を実行したターミナルが開いたままか、エラーで止まっていないか確認してください |
| NASに画像が保存されない | `.env` のSMB関連の設定（ホスト名・共有名・ユーザー名・パスワード）が正しいか、IT担当者に確認してください |
| status が `ERROR` になる | `error_message` 列の内容を確認してください |
| 文字がぼやけて読みにくい | Googleの仕組み上の画像解像度の上限に関する既知のリスクです。開発担当者に実測サイズ（Apps Scriptの実行ログに出力されます）を共有してください |

これでも解決しない場合は、ターミナルに表示されているエラーメッセージを
そのままコピーして、開発担当者（このシステムを作った人）に共有してください。
専門用語が多い内容でも構わないので、そのまま貼り付けてもらえれば十分です。
